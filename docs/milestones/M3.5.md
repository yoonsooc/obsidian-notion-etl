# M3.5 리뷰 (이관 범위 확장: Daily → Work 전체)

기간: 2026-09-01
상태: 완료. 실제 migrate는 사용자가 수행(Weekly.md exclude 추가 후 신규 14건 생성, 총 84페이지),
백업 미러도 제목 기준 파일명으로 84건 재구축
결정: D14(노트 정체성은 제목 — 중복 검사·백업 파일명), D15(범위 확장) — PRD 반영 완료

## 배경

toNotion.target을 `Work/Daily`에서 `Work`로 넓혀 Weekly(`WG_260513-0517`)·Monthly(`MG_202603`)까지
이관 대상에 포함한다. 사용자가 지적한 백업본 재이관 루프(백업 디렉토리가 Work 하위)와,
분석 과정에서 드러난 중복 검사 충돌(주간/월간 시작일 = 데일리 날짜)을 함께 해결했다.

## 산출물

- **백업-소스 중첩 가드** (internal/config): validate에 `isWithin`(조상 경로 SameFile 비교) 추가.
  백업⊂소스(재이관 루프)와 소스⊂백업(미러 덮어쓰기) 양방향 차단, MkdirAll 전에 검사.
  기존 동일성 가드는 중첩을 잡지 못했음(테스트 2건 추가)
- **중복 검사 제목 기준 전환** (D14, internal/cli/migrate.go): Date 우선 검사와 claim 키를
  제목으로 통일. `notion.ExistsByDate` API와 테스트 제거. 가이드 Q4가 현실화된 사안
- **platinum 확장** (plugin/platinum.go):
  - DateRules에 `MG_200601` 추가 — 월간은 레이아웃 선언만으로 1일 파생 (일 미지정 → 1)
  - `weeklyStartDate` 커스텀 Transformer — WG_ 파일명에서 시작일 파생. 실데이터에 구분자
    `-`/`~`와 끝 4/6자리(`WG_260831~260906`)가 혼재해 모두 수용. **선언 체인의 created_date
    폴백을 덮어쓴다**(주간도 데일리와 같은 frontmatter를 가져서, 덮지 않으면 작성일이
    시작일 자리를 차지). 유형별 별도 플러그인은 두지 않음 — 실행당 플러그인 1개 구조이고
    날짜 체인이 유형 디스패처 역할
  - plugin 패키지 첫 테스트(platinum_test.go): 규칙 검증, 월간 파싱, 주간 8케이스
- **파일 권한 통일**: vault.WriteNote에 CreateTemp(0600) 후 Chmod 0644 추가(latest.go 패턴),
  테스트로 고정. 기존 백업본 70건도 644로 정리

## 운영 전환 (수행 완료)

1. 백업 디렉토리 이동: `Work/Daily-NotionBackup` → `100. Inbox/Daily-NotionBackup` (사용자 수행)
2. 옛 백업 디렉토리 삭제 + 워터마크(lastBackupRunAt) 리셋 (사용자 수행)
3. toNotion.target → `100. Inbox/Work`, init 재실행(스냅샷 아카이빙)
4. 전체 백업 재수행: 새 디렉토리에 70건 미러 복원 (권한 644 확인)

## 추가: 백업 파일명 제목 기준 전환 (D14 확장, 2026-09-01)

사용자 지적: migrate가 파일명 어간을 제목으로 보존하는 이상 백업 파일명도 제목 기준이어야
대칭이다. Date 기준(M3 초기 구현)은 D15 이후 같은 날짜의 DN/WG가 `-2` 접미사로 충돌하고
원본 이름을 잃는다.

- backupFileName을 제목 → Date → 페이지 ID 순으로 변경, cli 패키지 첫 테스트(backup_test.go) 추가
- 전환: 날짜명 미러 전체 삭제 + 워터마크 리셋 + 전체 재백업. 84건(사용자가 실제 migrate 수행 후)
  전건 원본 이름 복원, 접미사 충돌 0건, `~` 구분자 주간 파일명도 그대로 보존
- 발견: 제목이 빈 노션 페이지 1건이 ID 파일명(`3c304159-....md`)으로 남음 — 본문도 빈
  페이지(2026-08-21 수정)라 노션에서 정리 후보
