## 스레드 1: Go 1.27 업그레이드 (`98fc7c3`)

2026-08 릴리즈된 Go 1.27로 상향. 사전 호환성 점검 결과와 함께 진행.

- go.mod 디렉티브 `1.26.5` → `1.27`. `GOTOOLCHAIN=auto`가 빌드 시 1.27 툴체인을 자동 다운로드하므로
  README 요구사항을 "Go 1.27+"로 갱신 (구버전 사용자도 auto면 빌드 가능, local 고정이면 명시적 에러)
- 호환성 점검: gopls v0.23.0(1.27 대응 릴리즈)은 유지, **staticcheck는 2026.1 → 2026.2.1 업그레이드 필수**
  (제네릭 메서드 등 새 문법 지원이 2026.2부터). 의존성 3종(x/time, x/text, yaml.v3)은 문제없음
- 새 staticcheck 지적 S1016 반영: `DataSourceRef{ID: ds.ID, ...}` → `DataSourceRef(ds)` 타입 변환
- encoding/json이 내부적으로 json/v2 엔진으로 교체됨(v1 API 의미 유지). 실제 Notion API 응답 파싱을
  `migrate --dry-run`(중복 검사가 쿼리 응답 파싱을 강제)으로 검증, 이상 없음. 문제 시 `GOEXPERIMENT=nojsonv2` 폴백
- 활용 후보로 남긴 1.27 피쳐: 제네릭 메서드, `uuid` 표준 패키지(노션 ID 파싱), 고루틴 누수 프로파일(워커 풀)

## 스레드 2: 플러그인 아키텍처 (`faf8488`, `867ed1d`)

M2의 pipeline.go(변환 정책 단일 출처, D10)가 커스텀 비즈니스 로직과 범용 글루의 혼재 문제로 지적되어,
단계적으로 플러그인 아키텍처로 재구성했다. D10의 "규칙은 코드로" 결정은 유지하되 위치와 계약을 정리한 것.

### 진행 단계 (사용자 지적 → 반영 순서)

1. **분리**: pipeline.go의 커스텀 정책(날짜 규칙, Platinum 매핑, nfcTitle)을 `plugin/`으로,
   범용 변환 글루(config 규칙 → transform 타입)를 `internal/pipeline/`으로 분리
2. **접합부 일원화**: 공통부(init/migrate)가 plugin 패키지에 직접 의존하는 문제를 해소.
   `pipeline.Plugin` 인터페이스(Name/DateRules/Mapping/Transformers, 전부 선언적이라 실패하지 않음),
   `Register`/`Select` 레지스트리, `BuildChain` 체인 조립. plugin 패키지 참조는 main.go의
   blank import 한 줄뿐 (init()에서 자가 등록)
3. **이름과 선택**: 파일명을 pipeline.go → `platinum.go`(개인 정책임을 명시),
   base.config.yaml의 `pipeline.plugin` 키로 사용할 플러그인 선택 (Quartz 방식)
4. **내장 default 플러그인**: 사용자 플러그인 코드가 전무한 초기 상태에서도 동작하도록
   `internal/pipeline/default.go` 추가. 규칙은 base.config.yaml의 `pipeline.dateFrom/mapping`(yaml,
   코드 수정 없이 편집 가능)에서 오고, 없으면 일반 관례로 폴백(파일명 `2006-01-02` → fm `date` → `created`,
   매핑 없음). M2에서 코드로 옮겼던 설정 기반 규칙이 opt-in으로 복원된 셈
5. **파일 분리 + 구현 검증**: pipeline.go(계약·레지스트리·선택) / default.go(내장 플러그인) /
   chain.go(체인 조립·NFCTitle·변환 헬퍼)로 관심사 분리. `var _ Plugin = ...` 컴파일 타임
   구현 검증을 defaultPlugin, nfcTitle, platinum에 추가 (Uber 가이드 Verify Interface Compliance)

### 주요 설계 결정과 근거

- **플러그인 계약은 선언적**: 모든 메서드가 규칙 데이터/트랜스포머 값만 반환하고 실패하지 않는다.
  규칙 오류는 init 검증(ValidateMapping/ValidateDateRules)에서, 노트 단위 변환 에러는 transform.Run에서
  격리되므로 플러그인 에러가 접합부로 전파되지 않는다
- **default 선택 규칙**: `plugin: 'default'` 명시, 또는 생략 시 등록 0개면 default / 1개면 그것 /
  2개 이상이면 목록을 보여주는 에러. 복수 등록 상태의 암묵적 기본값은 의도적으로 없음.
  `default`는 예약어(Register가 패닉으로 거부)
- **yaml 규칙은 default 전용**: 사용자 플러그인과 `pipeline.dateFrom/mapping` 동시 지정은 조용한 무시가
  아니라 에러 (strict 파싱 철학과 일치). latest.config.yaml의 dateFrom/mapping은 검증 후 **기록용 출력**이며
  Select로 흘러가는 경로가 없다 (base=입력, latest=출력 스냅샷)
- **default를 plugin/이 아닌 internal에 둔 이유**: (a) Select가 직접 생성해야 하는데 plugin/에 두면
  internal/pipeline ↔ plugin 순환 참조, (b) 레지스트리 등록은 시작 시점이지만 default 규칙은 그 뒤에
  로드되는 설정에서 오므로 등록 방식과 궁합이 안 맞음(mutable 전역 금지와 충돌), (c) 사용자가 지우거나
  교체할 수 없는 프레임워크 기능이라는 의미론. 검토 후 이동하지 않기로 결정 (2026-08-29)
- **NFC 제목 정규화 공용화**: nfcTitle을 platinum 전용에서 `pipeline.NFCTitle()`로 승격,
  default/platinum 공유. transform 패키지의 의도적 무의존(x/text 미사용)은 유지
- **latest에 plugin 이름 스냅샷 기록** (`latest.plugin` 필드): 어느 플러그인으로 생성된 스냅샷인지 추적

### 검증

- gofmt / go vet / staticcheck 2026.2.1 클린, `go test -race ./...` 전체 통과
- 접합부 단위 테스트 신설 (internal/pipeline/pipeline_test.go): 선택 로직 6개 시나리오, 폴백 규칙
  유효성, 체인 삽입 순서(dateDeriver → titleFromFilename → 커스텀 → obsidianURI → propertyMapper).
  main 패키지 시절 테스트 공백(셀프 리뷰 가이드 Q2)이 internal 이동으로 해소됨
- 실환경 E2E: init(매핑 2건 검증, latest 재생성·아카이빙) + migrate --dry-run 69건

## 스레드 3: 컨벤션 문서화 (커밋 없음 — 대상이 전부 gitignore)

  방향은 패키지/함수 이름이 표현한다 (backup에서 입출력이 뒤집혀도 규칙 불변). 산출물 타입은 `Draft` 접미사

  notion에 Obsidian 어휘 금지 (혼용은 변환 패키지에서만). 중립 어휘만 충돌 지점에 PascalCase 접두사
