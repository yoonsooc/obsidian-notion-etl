# v1.2.0 — 출력 언어 정책: 영어 정본화 + stdout 지역화

기간: 2026-09-16
상태: 완료. 언어 4경로(기본 en / config ko / env ko / env가 config를 덮음) 실측 검증
결정: [D18](../decisions/D18-output-language.md)

## 산출물

- **영어 정본화 스윕**: 에러 값 93건(전 10개 패키지), 로그 호출 18건, 변환 경고 4건을
  영어로 전환 (Go 관례: 소문자 시작·마침표 없음). 한글 문구를 단언하던 테스트들을
  새 영어 문구로 갱신. 이제 비테스트 Go 코드의 한국어는 의도된 두 곳
  (helpKO, catalog_ko.go)에만 존재
- **stdout 지역화 계층** (internal/cli):
  - lang.go: `NewPrinter(configLang)` — ETL_LANG > config lang > en 해석,
    sync.Once로 한국어 카탈로그 등록(init() 금지 컨벤션 준수). `FprintUsage`로
    usage를 cli 단일 정본화(main과의 문자열 드리프트 제거)
  - catalog_ko.go: 영어 원문을 키로 하는 수동 카탈로그(약 18키 + usage).
    누락 키는 영어 폴백
  - init/migrate/backup 요약·안내와 스케줄 메시지를 printer로 전환. 스케줄 플래그는
    설정을 로드하지 않으므로 ETL_LANG만 적용(문서화)
- **help 처리 이전(리팩토링)**: main.go에 남아 있던 help 처리(runHelp, helpEN/helpKO)를
  internal/cli/help.go로 이전해 main을 순수 라우팅으로 정리(다른 서브커맨드와 일관).
  usage(usageText/FprintUsage)도 lang.go에서 help.go로 이동. 이 과정에서 D18에 문서화된
  help 언어 우선순위(--lang 플래그 > ETL_LANG > en)를 실제 구현에 반영
  (기존에는 ETL_LANG을 무시했음)
- **설정**: base.config.yaml 최상위 `lang: 'ko'`(기본 en, en/ko 외 값은 로드 에러).
  example에 주석 안내
- **cron 영어 고정**: `--schedule` 생성 라인에 `ETL_LANG=en` 포함 — config가 ko여도
  cron.log는 영어. 운영 crontab을 새 형식으로 재등록 완료

## 검증

- gofmt/vet/staticcheck(ST1005 대문자 에러 문자열 포함) 클린, 전체 테스트 통과
- 언어 경로 실측: 기본 en / `ETL_LANG=ko`(usage·status 한국어) / config `lang: 'ko'`만으로
  dry-run 요약 한국어 / config ko + `ETL_LANG=en`이 영어로 덮음
- help 경로 실측: 기본 en / `ETL_LANG=ko`로 한국어 / `ETL_LANG=ko` + `--lang=en`이
  플래그 우선으로 영어 / `--lang=fr`·미지원 인자 에러
- 재등록된 cron 라인에 ETL_LANG=en 포함 확인, 스케줄 테스트의 라인 생성·감지 회귀 없음
- 참고: 이 시점 실DB는 99페이지(실사용 증가분). dev 스냅샷은 검증용 dry-run만 수행
