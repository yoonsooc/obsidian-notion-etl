# v1.1.0 — help 명령과 backup 스케줄 관리 플래그

기간: 2026-09-16
상태: 완료. 실 crontab 대상 E2E 5단계 통과
결정: [D17](../decisions/D17-backup-schedule-flags.md) — v1 이후 첫 ADR

## 산출물

- **전역 help**: `etl-worker help`(-h/--help 동일)가 명령·플래그·대표 흐름·운영 홈 주의를
  stdout으로 출력. 인자 오류 시의 짧은 usage(stderr)와 분리하고 usage 말미에 help 안내.
  기본은 영문이고 `--lang=ko`로 한국어 본문 선택(두 본문을 상수로 병행 유지, 미지원
  언어는 에러). CLI가 공개 도구인 이상 기본 표면은 영문이라는 사용자 결정
- **backup 스케줄 관리 플래그** (internal/cli/schedule.go 신설):
  - `--schedule[=<크론식>]`: 엔트리를 사용자 crontab에 등록. 크론식은 5필드
    표현식이며 생략 시 `0 * * * *`(매시 정각). 필드 수·문자 집합을 사전 검증하고
    (의미 검증은 cron 몫), 이미 있으면 기존 라인 안내(중복 등록 방지). 라인은 실행
    시점 디렉토리·바이너리 절대경로를 인용해 생성
  - `--unschedule`: 이 도구의 엔트리만 제거, 다른 crontab 항목 보존. 전부 비면 빈 crontab
  - `--status`: 등록 여부와 등록된 라인 출력
  - 스케줄 플래그는 상호 배타이며 --dry-run과 조합 불가
- 설계: 순수 라인 조작 함수(hasBackupEntry/addBackupEntry/removeBackupEntry/cronLine)와
  crontab exec 래퍼를 분리해 조작 로직을 단위 테스트(4개 테스트, 15케이스). 엔트리 식별은
  인용 제거 후 `etl-worker backup` 포함 여부라 레거시 수기 라인도 감지
- crontab 쓰기 실패 메시지에 macOS TCC 힌트("터미널에서 실행") 포함

## 검증

- gofmt/vet/staticcheck 클린, 전체 테스트 통과 (cli 테스트 19케이스로 확대)
- CLI 표면: help(stdout·exit 0), 무인자/오류(usage stderr·exit 1) 확인
- 실 crontab E2E: status(레거시 수기 라인 감지) → unschedule(제거) → status(미등록) →
  schedule(절대경로 인용 라인 등록) → status와 crontab -l 일치. 기존 운영 엔트리가
  새 형식으로 교체되어 연속성 유지
- 참고: 이 세션(VSCode) 컨텍스트에서 crontab 쓰기가 TCC 심사로 수 분 지연됐으나 성공.
  터미널에서는 즉시 동작
